Code Agent — Interaction Prototype

A local web workbench over the Claude Agent SDK (TypeScript). Every screen below is drawn entirely in SVG. Numbered markers point at interactive elements; the table under each screen explains the interaction, what the UI does, and which SDK surface it relies on. Requirement IDs (FR-…) refer to docs/requirements.md.

How to read

Annotation marker. Click a marker to jump to its note; hover a note to highlight its marker.
Accent — primary actions, selection, running state.
Warning — needs the user's input (always with an icon and a label).
Critical — errors, destructive actions, bypass mode.
Good — completed, connected, approved.
Dashed outline — collapsed or secondary content (thinking, drafts).

Canvas size is 1440 × 900 (a 1440 px wide desktop browser). Each screen has buttons to open the SVG on its own or download it. The prototype is static: states that would follow an interaction are shown as separate screens or variants.

Global interactions

AreaRule
KeyboardCtrl K command / search · Ctrl N new session · Enter send, Shift Enter newline · Esc interrupt the running turn (when the composer is empty) · Ctrl B move running work to the background · Shift Tab cycle permission mode · 1–4 pick an option in approval / question panels · Ctrl . toggle inspector · Alt ↑/↓ switch live session.
Real timeEvery live session streams over one WebSocket. Each event has a sequence number; after a reconnect the client asks for events after its last sequence and the server replays them. Nothing in the UI is "fire and forget": every command shows pending → done / failed.
Session stateThe SDK's session_state_changed drives one indicator used everywhere: a blue ring = running, amber dot + "Needs …" = requires action, grey = idle. The browser tab title gets a prefix (● / !) and the favicon a badge.
Needs-input priorityWhen a session needs input (approval, question, plan, elicitation), the request docks above the composer. If the user is in another session or tab, the top-bar bell counts it and an (opt-in) browser notification is sent. Answering anywhere resolves it everywhere.
Destructive actionsDelete session, rewind files, bypass permissions and clearing the conversation always ask for confirmation, and say what cannot be undone.
Version gatingFeatures the running Claude Code version lacks (read from the init message) are hidden or shown disabled with the minimum version in a tooltip.
Empty, loading, errorLists show an empty state with the primary action; loading uses skeleton rows; errors show the SDK error text with a retry action. See P24 for session-level states.
